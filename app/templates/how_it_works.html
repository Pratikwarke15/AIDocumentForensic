Academic Methodology & Technical Pipeline

Based on the academic paper: "SpliceFound: A Web-Based Image Splicing Detection Tool Using Error Level Analysis (ELA)" and enhanced with trained Random Forest classification for document security.

1. Error Level Analysis (ELA) Pipeline

Primary Signal

When a JPEG image is saved, the compression algorithm introduces loss in 8x8 pixel blocks based on a quantization table. If an authentic document is saved once, all regions exhibit uniform error rates. However, if a fraudster modifies a number or pastes a name, that modified patch undergoes a different compression cycle.

The ELA Algorithm:
1. Standardize image to max 800x800 dimensions.
2. Recompress image in-memory at JPEG quality factor Q = 95.
3. Compute absolute difference: Δ = |I_original - I_recompressed|.
4. Amplify differences by Scale Factor S = 15.0.
5. Map amplified difference to Jet color spectrum (Blue = Low error, Red = High anomaly).
6. Apply thresholding and morphological filtering to localize suspicious contours.

2. Machine Learning Enhancement: Beyond Fixed Thresholds

Core Research Improvement

Prior systems (such as baseline SpliceFound) rely on a single empirical threshold (e.g. 0.02 tamper pixel ratio) to classify an image as forged. In real-world government documents, variations in scanning resolution and background noise make a single threshold unreliable.

Our system replaces the rigid threshold with a Random Forest Classifier trained on 28+ numerical features:

  • Statistical moments: Mean, Standard Deviation, Variance, Skewness, Kurtosis.
  • Percentiles: 75th, 90th, 95th, and 99th percentiles of error distribution.
  • Localization metrics: Connected component count, max component area ratio, component density.
  • Multi-signal corroboration: Local noise variance disparity, JPEG blockiness discontinuity, ORB copy-move duplication clusters, and sharpness disparity.

3. Local Verification Registry (Phase 1)

Record Verification

In Phase 1, the platform operates a local simulation registry stored in /verification_records/ with subfolders for Aadhaar, PAN, Marksheets, Certificates, Caste, Income, and Domicile documents. The database maintains a fast indexed cache that automatically synchronizes with folder changes.

Ethical & Legal Notice: Missing records from the local registry result in "RECORD NOT FOUND", indicating absence from the prototype demonstration database rather than conclusive invalidation of authentic government documents.
